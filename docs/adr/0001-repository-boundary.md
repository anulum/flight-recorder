# Repository boundary

Status: accepted for local tooling construction.

FLIGHT-RECORDER owns repository validators now. Its planned responsibility is bounded local capture, segments, surviving checkpoints, distinct triggers, permitted offload and gap-honest reconstruction. SystemVerilog instrumentation and Python simulation/library/CLI are future complete counterparts.

Common evidence representation and signing stay Toolkit-owned; qualified software adapters own sealing without inventing a hardware signer. The recorder does not aggregate fleet health, own deployment packages, actuate a unit or replace global lineage. LTW method reuse does not authorize copying its implementation.

Retained-window integrity, anchored knowledge of earlier ranges and full required-reference admission are separate results. A valid chain cannot establish events that were never recorded. A checkpoint cannot waive missing required predecessor lookup. Prior source and capture/sharing policies constrain every output.

The planned segment identifier is separate from registered or qualified formats. Future changes must add genuine public producers and separate consumers, actual source qualification, complete negative cases, strict checks, tests, docs and native benchmark parity in the same complete change.
